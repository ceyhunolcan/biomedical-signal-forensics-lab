# Push to GitHub

The repo in `biomedical-signal-forensics-lab-v0.7.1.zip` is fully initialized as a git repo with one commit on the `main` branch. To push it to a GitHub account from your Mac, follow the steps below.

## One-time setup (skip if already done)

1. Install GitHub CLI if you don't have it: `brew install gh`
2. Authenticate: `gh auth login` and follow the prompts. Pick HTTPS for the protocol.

## Push to a new GitHub repo

```bash
# 1. Unzip the release somewhere you want it to live
cd ~/Documents   # or wherever
unzip ~/Downloads/biomedical-signal-forensics-lab-v0.7.1.zip
cd biomedical-signal-forensics-lab

# 2. Confirm the local repo is intact
git log --oneline
# expected: one commit "Initial commit: biomedical-signal-forensics-lab v0.7.1"

# 3. Create the GitHub repo and push (one command with gh CLI)
gh repo create biomedical-signal-forensics-lab \
    --public \
    --description "A reliability framework for wearable-derived digital biomarkers, with real-data validation on WESAD" \
    --source . \
    --push

# If you want it private instead, replace --public with --private.
```

That command does three things at once: creates the GitHub repo under your account, sets the local repo's `origin` remote to point at it, and pushes the `main` branch.

## Alternative without gh CLI (web UI)

If you prefer to create the repo from github.com first:

```bash
# 1. Go to github.com -> "+" -> "New repository"
#    Name: biomedical-signal-forensics-lab
#    DO NOT initialize with README, .gitignore, or LICENSE -- the local
#    repo already has all of these. Initializing would create a conflict.

# 2. Copy the SSH or HTTPS URL GitHub shows. Example:
#    HTTPS: https://github.com/YOUR_USERNAME/biomedical-signal-forensics-lab.git
#    SSH:   git@github.com:YOUR_USERNAME/biomedical-signal-forensics-lab.git

# 3. In your local clone:
cd biomedical-signal-forensics-lab
git remote add origin https://github.com/YOUR_USERNAME/biomedical-signal-forensics-lab.git
git push -u origin main
```

## After the push

1. Verify the CI workflows ran successfully on GitHub Actions: visit
   `https://github.com/YOUR_USERNAME/biomedical-signal-forensics-lab/actions`
   You should see two workflows on the first push: `tests` (runs the 202-test
   suite on Python 3.10, 3.11, and 3.12 plus a pipeline smoke test) and
   `lint` (ruff check, ruff format check, and the em-dash gate).

2. Confirm the README badges resolve. Edit `README.md` and replace the
   `PLACEHOLDER` URL fragments with your actual GitHub username, then
   commit and push:

   ```bash
   sed -i '' 's/PLACEHOLDER/YOUR_USERNAME/g' README.md CHANGELOG.md
   git add README.md CHANGELOG.md
   git commit -m "Replace PLACEHOLDER with actual GitHub username in README + CHANGELOG"
   git push
   ```

3. If you want a versioned release, tag and push the tag:

   ```bash
   git tag -a v0.7.1 -m "v0.7.1: bug fixes after v0.7.0 reviewer-grade extended analyses"
   git push origin v0.7.1
   ```

   This triggers the release tooling if you want to publish a GitHub Release
   (you can do that from the Releases tab on the repo page).

## Common issues

**Authentication failure on push.** Run `gh auth status`. If gh is not
authenticated, `gh auth login`. For HTTPS pushes without gh CLI, you may
need a personal access token from https://github.com/settings/tokens.

**"Updates were rejected because the remote contains work that you do not have locally."** This happens if you accidentally initialized the GitHub
repo with a README. Either delete the GitHub repo and recreate without the
README, or run `git pull --rebase origin main` first.

**Repo size warning.** The repo is 5.1 MB (mostly figures). GitHub
accepts this without warning. If you want to slim it down, the figures in
`paper/figures/` are regenerable from the scripts; you could move that
directory under `.gitignore` and regenerate on demand.

**Large file warning if you re-add results/.** The `.gitignore` excludes
`data/synthetic/*.csv`, `data/synthetic/*.npz`, and `results/figures/*.png`
because they are regenerated by the pipeline. Do not `git add -f` these
unless you are sure you want them in version control. The paper figures
in `paper/figures/` are intentionally committed and that is the right
place for them.
