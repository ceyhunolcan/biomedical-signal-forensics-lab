# Visual polish setup walkthrough

Tier 3 visual polish for the repository. These are mostly one-time manual
clicks in the GitHub UI - the assets and snippets are auto-generated by
`bash apply_v0_17_0.sh`.

Expected total time: ~10 minutes.

## 1. Upload the social preview image (2 min)

The social preview is what shows up when someone shares the repo link on
Twitter, LinkedIn, Slack, Discord, or any site that scrapes Open Graph tags.

  1. Go to https://github.com/ceyhunolcan/biomedical-signal-forensics-lab/settings
  2. Scroll down to the "Social preview" section
  3. Click "Edit" then "Upload an image"
  4. Choose `docs/assets/social_preview.png` from the repo
  5. Save

To verify: paste your repo URL into https://opengraph.dev/ or share it once in
a Slack or Discord channel. The image should appear in the link preview.

## 2. Set the repository "About" panel (3 min)

The "About" panel is the box on the right side of the repo home page. People
read it first, so it should be tight.

  1. From the repo home page, click the gear icon next to "About"
  2. Set the fields:

| Field | Value |
|---|---|
| Description | An open-source Python toolkit for auditing wearable physiological signal pipelines. |
| Website | https://ceyhunolcan.github.io/biomedical-signal-forensics-lab/ |
| Topics | wearables, ppg, ecg, signal-quality, fairness, causal-inference, reproducibility, digital-health, wesad, biostatistics |
| Releases | check (already on) |
| Packages | uncheck unless you have GitHub Packages enabled |
| Deployments | check (this turns on the green "github-pages" environment) |

  3. Click "Save changes"

## 3. Pin the repository on your personal profile (1 min)

Pinned repos appear at the top of your https://github.com/ceyhunolcan profile,
above the contribution graph. Six slots.

  1. Go to https://github.com/ceyhunolcan
  2. Click "Customize your pins"
  3. Check `biomedical-signal-forensics-lab`
  4. Drag it to the top-left slot if you have multiple pins
  5. Save

## 4. Update the README with the new snippets (2 min)

The apply script writes the new README hero block and architecture diagram to
`README_SNIPPETS.md`. To merge them in:

  1. Open `README.md` in your editor
  2. Replace the existing title and badges block (top of file, everything before
     the first H2 heading) with snippet 1 from `README_SNIPPETS.md`
  3. Insert snippet 2 (Architecture mermaid diagram) immediately after the
     intro paragraph, before the existing "Quick start" or "Installation"
     section
  4. Insert snippet 3 (Key results table) immediately after snippet 2
  5. Commit and push:

```bash
git add docs/assets/social_preview.png README.md README_SNIPPETS.md
git commit -m "v0.17.0: visual polish - social preview, hero, mermaid architecture, expanded badges"
git push
```

## 5. Verify mermaid rendering (30 sec)

Open `README.md` on GitHub at
https://github.com/ceyhunolcan/biomedical-signal-forensics-lab and confirm the
mermaid diagram renders as a coloured flowchart. If it shows as raw code,
GitHub has likely disabled mermaid for some reason - swap in the static SVG
fallback in `docs/assets/architecture.svg` (also generated by the script).

## 6. Optional: enable Discussions (1 min)

Discussions turn the repo into a community hub - good for Q&A, RFCs, and
"show and tell" posts.

  1. Settings -> General -> scroll to "Features"
  2. Check "Discussions"
  3. Save

A "Discussions" tab appears in the repo nav. Optional but appreciated by
contributors.

## 7. Optional: add a CITATION.cff file (already done in v0.13.0)

Already in place. The "Cite this repository" button on the repo page (above
"About") uses this file. Verify it's clickable and produces a valid BibTeX
entry.

## Done

Repository should now look polished from first glance:
- A bold social card when the URL is shared
- A clean hero image at the top of the README
- An architecture diagram that explains the toolkit visually
- A complete row of badges showing version, downloads, docs, tests, DOI, license
- A tight "About" panel with topics and a website link
- Pinned on your profile so visitors see it first
